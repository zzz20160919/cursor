## 4. Event Grid Definition

Implemented grids:

- `monday_0930`: Monday 09:30 `America/New_York`.
- `sunday_1700`: Sunday 17:00 `America/Chicago`.

Events are generated by iterating local calendar dates, then localizing the event wall time and converting to UTC. This avoids DST drift. A first implementation that added timezone-aware `Timedelta(days=1)` across DST missed the final Monday event; this was fixed by date-based iteration.

## 5. BTC Feature Calculation

Supported lookbacks:

- `1h`
- `4h`
- `1d`
- `2d`

BTC return columns use log returns:

- `btc_ret_<lookback> = log(close_end / close_start)`

Endpoint convention:

- Event time is converted to UTC.
- End key is `event_time_utc.floor(btc_bar_freq)`.
- Start key is `(event_time_utc - lookback).floor(btc_bar_freq)`.

Important parity detail:

- The old BTC input was a 1h CSV where `timestamp` was the bar open but `close` was the close of that full hour.
- The new BTC source is 1m parquet. To reproduce old 1h returns, the builder resamples 1m BTC to left-labeled hourly bar-close values when `--btc-bar-freq 1h` is used.
- Without this resampling, using the exact 1m close at the hour boundary produces materially different BTC returns.

## 6. NQ Forward Return Calculation

Supported forwards:

- `5m`
- `10m`
- `30m`
- `1h`
- `4h`
- `1d`
- `2d`

NQ return columns use log returns:

- `nq_fwd_<forward> = log(close_end / close_start)`

Endpoint convention:

- Start key is `event_time_utc.floor("1min")`.
- End key is `(event_time_utc + forward).floor("1min")`.
- Price is NQ 1m close at the endpoint key.

The new Step 2 builder uses the configured NQ input directly. In the parity run, that input was continuous `NQ.v.0` parquet, not the old raw-symbol active-contract CSV set.

## 7. Timezone Handling

The implementation uses timezone-aware pandas timestamps throughout:

- BTC timestamps are parsed to UTC.
- NQ timestamps are parsed to UTC.
- `monday_0930` is generated in `America/New_York`.
- `sunday_1700` is generated in `America/Chicago`.
- Output includes `event_time_ny`, `event_time_chicago`, and `event_time_utc`.

The old Monday event `2026-03-09` correctly appears as:

- `event_time_ny = 2026-03-09T09:30:00-04:00`
- `event_time_chicago = 2026-03-09T08:30:00-05:00`
- `event_time_utc = 2026-03-09T13:30:00+00:00`

## 8. Dataset Schema

The event dataset includes:

- Event identity and timestamps: `event_id`, `event_name`, `event_time_ny`, `event_time_chicago`, `event_time_utc`.
- Source paths: `btc_source_path`, `nq_source_path`.
- BTC endpoint prices and timestamps for each lookback.
- BTC returns: `btc_ret_1h`, `btc_ret_4h`, `btc_ret_1d`, `btc_ret_2d`.
- NQ endpoint prices and timestamps for each forward.
- NQ forward returns: `nq_fwd_5m`, `nq_fwd_10m`, `nq_fwd_30m`, `nq_fwd_1h`, `nq_fwd_4h`, `nq_fwd_1d`, `nq_fwd_2d`.
- Primary pair diagnostics: `signal_btc_ret_4h`, `gross_strategy_ret_monday_0930_4h_1d`, `net_strategy_ret_monday_0930_4h_1d_cost_001`.
- Data quality flags: `btc_feature_ok`, `nq_target_ok`, `nq_session_gap_warning`, `missing_data_reason`.

`nq_target_ok` refers to the primary target `nq_fwd_1d`. Other forward-window gaps still set `nq_session_gap_warning` and are recorded in `missing_data_reason`.

## 11. Differences Versus Old Output

BTC:

- Exact parity is achieved when the new 1m BTC parquet is resampled to old-style 1h bar-open labels with bar-close values.
- This confirms the BTC difference risk was endpoint convention, not event timezone.

NQ:

- Continuous NQ parquet does not exactly match old active-contract raw-symbol outputs.
- Many sampled NQ values match exactly, but some differ, including the first Monday event across multiple short forwards and larger differences for `2d`.
- This is expected because old logic picked one raw-symbol active contract per event using a fixed roll chain, while the new input is Databento continuous volume-front `NQ.v.0`.

Session gaps:

- `nq_session_gap_warning` surfaces missing endpoint cases, especially around `2d` windows that hit holidays or unavailable session bars.
- The primary target `nq_fwd_1d` is available for all 66 Monday rows in the parity range.

## 12. Can Continuous NQ Replace Old Active-Contract Logic?

Not for exact historical parity.

The continuous NQ parquet is usable for a clean new research dataset, but it is not an exact replacement for the old raw-symbol active-contract logic. It can preserve event row counts and much of the return behavior, but it changes some endpoint prices and therefore changes exact NQ forward returns.

For exact old-output reproduction, the next step should support the old raw-symbol NQ clean CSV set and active-contract assignment. For a forward-looking cleaner research branch, continuous NQ can be used, but results should be labeled as continuous-NQ semantics rather than old active-contract parity.
